==================== وصف النظام (المصدر) ====================

**نظرة عامة:** منصّة تشغيل متكاملة لشركة «Energize» اللوجستية السعودية، تخدم خطّي عمل: B2B (الشحن، CFS، التحصيل) و B2C (التوصيل للميل الأخير / مندوبي المبيعات). نظام داخلي واحد تدخل عليه كل الأقسام (المالية، العمليات، الورشة، الموارد البشرية، CRM، المبيعات، المحاسبة) بصلاحيات حسب الدور، وواجهة ثنائية اللغة (عربي/إنجليزي مع دعم RTL كامل)، وتحديثات لحظية عبر WebSockets.

**التقنيات:**
- Backend: Node.js، Express، MongoDB (Mongoose)، Socket.io، مصادقة JWT عبر كوكيز HTTP-only.
- Frontend: Next.js (App Router)، React، TypeScript، Tailwind CSS، Framer Motion، lucide-react.
- التحديث اللحظي: Socket.io — الخادم يبثّ أحداثاً، والصفحات تشترك عبر `useSocket`.
- التعدّد اللغوي: قاموس ثنائي اللغة مخصّص، عربي + إنجليزي + RTL.
- التصدير لإكسل عبر مكتبة xlsx.
- البنية: مجلد `backend/` (نماذج، كنترولرز، راوتس، إعدادات، أدوات، سكربتات) و `frontend/` (صفحات `app/system/*`، مكوّنات، مكتبات، سياقات).

**التشغيل محلياً:** الباك إند `npm run dev` على منفذ افتراضي 5001؛ عند أول إقلاع يزرع النظام تلقائياً حساب super_admin وأنواع الإجازات الافتراضية وشجرة الحسابات والقوائم المرجعية الافتراضية (كلها idempotent). الفرونت إند `npm run dev`، ويوجّه كل طلبات `/api/*` لنفس الأصل ثم يعيد توجيهها للباك إند حتى تبقى كوكيز الجلسة first-party (مهم لـ Safari/iOS).

**المصادقة والجلسات:** تسجيل الدخول يصدر access token قصير العمر (15 دقيقة) + refresh token (7 أيام) في كوكيز HTTP-only؛ عميل الـ API يجدّد تلقائياً عند الحصول على 401 ويعيد الطلب. الوسيط `auth.js` يتحقق من التوكن ويتحقق من حالة التفعيل والقفل.

**الصلاحيات (RBAC):** الوسيط `rbac.js` عبر `authorize(...roles)` يحمي كل مسار. الواجهة تعكس ذلك: الشريط الجانبي يعرض فقط عناصر القائمة التي يسمح بها دور المستخدم، و`roleRoutes.ts` يوجّه كل دور لصفحة هبوط يملك بياناتها. كل دور جديد يجب تحديثه في 7 مواضع (enum النموذج، تحقق الراوت، الثوابت، سياق المصادقة، roleRoutes، قائمة التنقّل، تسميات الترجمة).

**الهيكل التنظيمي (تحديد المدير):** `ROLE_HIERARCHY` يربط كل دور بدور المدير الافتراضي (مثال: محاسب ← مدير مالي ← admin ← super_admin). الأدوار العليا (super_admin، client) بلا مدير. عند إنشاء مستخدم بدون مدير صريح، يُحلّ المدير تلقائياً، والنموذج يقترحه مسبقاً دون إجبار. المدير المباشر يقود سلسلة اعتماد الإجازات (طلب ← المدير ← الموارد البشرية).

**القوائم المرجعية القابلة للتعديل (Lookups) والإضافة السريعة — ميزة جديدة:** كل قائمة منسدلة وصفية في النظام (فئات المشتريات، فئات الموردين، صناعات العملاء، مصادر العملاء، أنواع وأحجام الشركات…) أصبحت **بيانات قابلة للتعديل وليست كوداً ثابتاً**:
- مجموعة عامة واحدة `Lookup` صفوفها `{ type, key, nameEn, nameAr, color, order, isActive, isSystem }`؛ ونوع القائمة `type` مُسجّل في `config/lookupTypes.js` الذي يحدّد الوحدة المالكة، والأدوار المسموح لها بالتعديل، والصفوف الافتراضية التي تُزرع مرة واحدة.
- واجهة برمجية واحدة: `GET /api/lookups?type=…` (قراءة متاحة لأي مستخدم مُسجّل)، و`POST/PUT/DELETE /api/lookups` (كتابة بصلاحية حسب النوع)، و`GET /api/lookups/types`.
- شاشة إدارة واحدة: **الإدارة ← القوائم المرجعية** (`/system/settings/reference-data`) تعرض كل الأنواع مجمّعة حسب الوحدة، وتتيح للأدوار المخوّلة الإضافة/التعديل/التفعيل/الحذف. العناصر الافتراضية محميّة من الحذف (تُعطّل بدلاً من حذفها) حتى لا يختفي مفتاح يعتمد عليه سير عمل.
- إضافة سريعة داخل أي قائمة منسدلة: مكوّن `ManagedSelect` يعرض زر **«+ إضافة»** أسفل القائمة، فيُحفظ العنصر الجديد فوراً ويُختار دون مغادرة النموذج؛ ومكوّن `VendorSelect` يفعل المثل للموردين (كيان حقيقي عبر `POST /api/vendors`).
- القيم المخزّنة لم تتغيّر (لا يزال يُخزّن مفتاح النص أو مُعرّف المورد)، فالميزة متوافقة رجعياً بالكامل.
- **عمداً ليست Lookups:** الحالات (حالة الطلب/الأمر/الفاتورة)، ومراحل الـ pipeline في CRM، وأنواع الحسابات — تبقى في الكود لأن منطق العمل يتفرّع على مفاتيحها بالضبط، وجعلها قابلة للتعديل قد يكسر سير العمل.

**الأدوار وسير العمل (جدول):**
- super_admin (الرئيس التنفيذي/التشغيلي): يهبط على Dashboard، يرى كل شيء + KPIs + المستخدمين/الإدارة، بلا مدير، الدور الوحيد الذي يدير المستخدمين.
- admin: كل شيء عدا بوابة إنشاء المستخدمين، مديره super_admin.
- moderator: الرئيسية، العملاء، العمليات، KPIs؛ مديره admin؛ إشرافي/قراءة.
- employee: العملاء والمالية (التحصيل)، المهام، الخدمة الذاتية؛ مديره admin؛ موظف تحصيل.
- operations_manager: العمليات، السائقون، الموردون، المحفظة، تحليلات المركبات؛ مديره admin.
- operations: العمليات، السائقون، الموردون، المحفظة؛ مديره operations_manager؛ مقيّد بالفرع.
- workshop_manager: الورشة بالكامل، المخزون، أنواع الصيانة؛ مديره admin.
- workshop_employee: الورشة، مهام الورشة، اللوحة؛ مديره workshop_manager.
- purchasing: مشتريات الورشة + المخزون، **ويُعاد استخدامه للمشتريات (موظف مشتريات)**؛ مديره workshop_manager.
- b2c_head: B2C بالكامل، يملك كل مشاريع B2C؛ مديره admin.
- b2c_project_manager: B2C (المشاريع المسندة)؛ مديره b2c_head.
- hr_manager: مكتب الموارد البشرية بالكامل + الخدمة الذاتية؛ مديره admin.
- hr_specialist: مكتب الموارد البشرية + الخدمة الذاتية؛ مديره hr_manager.
- crm_manager: CRM بالكامل (مع الحذف)؛ مديره admin.
- crm_specialist: CRM (بلا حذف)؛ مديره crm_manager.
- finance_manager: المحاسبة بالكامل (مع الحذف والقيود)؛ مديره admin.
- accountant: المحاسبة (CRUD بلا حذف)؛ مديره finance_manager.
- sales_manager: المبيعات بالكامل (يضع الأهداف)؛ مديره admin.
- sales_rep: المبيعات (خط أنابيبه وأداؤه فقط)؛ مديره sales_manager.
- procurement_manager: المشتريات بالكامل (يعتمد/يحذف)؛ مديره admin.
- remote_manager: العمل عن بُعد بالكامل؛ مديره admin.
- remote_employee: صفحات العمل عن بُعد المسموح بها في `remoteAccess` + الخدمة الذاتية؛ مديره remote_manager؛ صلاحية لكل صفحة على حدة.
- client: بوابة العميل (فواتيره ومدفوعاته فقط)؛ بلا مدير؛ دخول عميل خارجي.
- **الخدمة الذاتية (لكل دور داخلي):** ملفي، إجازاتي، طلباتي تحت الموارد البشرية.

**الوحدات:**
- العملاء والمالية (نواة B2B): العملاء، الفواتير، المدفوعات، التحصيل، المحصّلون، النزاعات، تنبيهات الائتمان، المتأخرات، المحفظة اليومية (نقد/مصروف/شراء لكل فرع). العمود المالي الذي تقرأ منه المحاسبة.
- العمليات: مسارات العمليات (مسودة ← عمليات ← تحصيل ← مكتمل)، كشوف الإرسال، السائقون، الموردون، المحفظة، تحليلات المركبات (الوقود، GPS، الرحلات، الرفع).
- الورشة: طلبات الصيانة، مهام الورشة، المخزون، طلبات الشراء، أنواع الصيانة.
- B2C: تتبّع الطلبات اليومية للمندوبين، إدارة المشاريع/الفروع/المندوبين، مزامنة Excel و Google Sheets، لوحات الأداء وتقييم المندوبين.
- العمل عن بُعد: الحضور، الإجازات، الدردشة، المهام، التقارير، الإعلانات — مع منح لكل صفحة عبر `remoteAccess`.
- الموارد البشرية: الموظفون، العقود، طلبات الإجازة (اعتماد المدير ← الموارد البشرية)، طلبات الموظفين، عُهد الأصول، أنواع الإجازات، وصفحات الخدمة الذاتية. احتساب رصيد الإجازات تدريجياً.
- CRM: الشركات (مع تقييم 0–5 نجوم + أزرار واتساب/اتصال/بريد/موقع مباشرة)، جهات الاتصال، الأنشطة، المهام، خط أنابيب صفقات بالسحب والإفلات، وتقويم. **هجين:** شركة CRM يمكن ربطها بعميل لوجستي قائم.
- المبيعات: مبنية فوق صفقات CRM (مالك الصفقة = المندوب). أهداف شهرية لكل مندوب/فريق، أداء (المُنجز مقابل الهدف بنسبة التحقيق)، عرض خط أنابيب للقراءة، ولوحة (قيمة المُنجز، معدل الفوز، أفضل المندوبين).
- المحاسبة: قيد مزدوج كامل — شجرة حسابات (أصول/خصوم/حقوق ملكية/إيراد/مصروف، تُزرع افتراضياً)؛ يومية بقيود متوازنة (المدين = الدائن) + ترحيل تلقائي؛ محرّك ترحيل تلقائي idempotent يمسح الفواتير (مدين ذمم مدينة، دائن مبيعات) والمدفوعات (مدين نقد، دائن ذمم) وحركات المحفظة وينشئ قيداً لكل مستند بمفتاح المصدر فلا يتكرّر؛ تقارير: دفتر الأستاذ، ميزان المراجعة، الأرباح والخسائر، أعمار الذمم المدينة.
- المشتريات: دورة شراء-حتى-الدفع كاملة — طلب شراء (ببنود وتبرير وأولوية) ← اعتماد (المدير) ← أمر شراء (المورد، ضريبة القيمة المضافة السعودية 15%) ← استلام ← فاتورة مورد (ذمم دائنة). إنشاء فاتورة المورد يرحّل تلقائياً قيداً متوازناً للمحاسبة (مدين مصروف + مدين ضريبة، دائن ذمم دائنة)؛ وتسجيل الدفع يرحّل مدين ذمم دائنة دائن نقد؛ وحذف الفاتورة يعكس قيودها. تقرير أعمار الذمم الدائنة يقرأ فواتير الموردين المفتوحة. **الموردون كيان مستقل** يُدار تحت العمليات ← الموردون (متاح الآن لـ procurement_manager / purchasing أيضاً) ويمكن إنشاؤه فوراً من أي نموذج مشتريات عبر زر «+ إضافة» في قائمة المورد. فئات الشراء قوائم مرجعية قابلة للتعديل.
- KPIs (للقيادة): لوحة تنفيذية واحدة تسحب رقماً رئيسياً من كل وحدة (الأرباح والخسائر + الذمم، خط أنابيب CRM/المبيعات + المُنجز، العملاء، عدد موظفي الموارد البشرية + الإجازات المعلّقة، طلبات B2C، العمليات المفتوحة).

**كيف ترتبط الوحدات:** العميل (B2B) ← الفواتير ← المدفوعات ← التحصيل ← المحفظة ← كلها تُرحَّل تلقائياً للمحاسبة (يومية ← دفتر أستاذ ← أرباح وخسائر/ميزان مراجعة/أعمار ذمم مدينة ودائنة). شركة CRM ترتبط اختيارياً بعميل. المورد ← المشتريات (طلب ← أمر ← فاتورة مورد) ترحّل ذمم دائنة. الصفقات (المالك = المستخدم) ← المبيعات (أهداف، أداء، خط أنابيب). المستخدم ← (موظف مرتبط) ← الموارد البشرية (عقود/إجازات/عُهد)؛ والمستخدم ← (المدير عبر ROLE_HIERARCHY) ← سلسلة اعتماد الإجازات. وكل ما سبق ← KPIs (نظرة تنفيذية للقراءة فقط).
